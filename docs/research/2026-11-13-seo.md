## Technical check (live site, 2026-11-13)

What's right: http and www redirect to `https://native-packages.dev/`; every sitemap URL answers 200 with one h1, a self-referencing canonical, a description under 160 characters, Open Graph and Twitter tags with a 1280x720 JPEG that answers 200, and JSON-LD that parses (WebSite, WebPage, BreadcrumbList). `robots.txt` names the sitemaps. No broken internal links.

What was wrong, and what this pass did:

| Issue | Done |
|---|---|
| Homepage title was the bare name "native-packages" (15 characters) | `seo.title` in `docs/index.md` |
| Guide titles named the topic but not what people search ("Windows code signing", "macOS and Windows installers", "Getting started") | `seo.title` on four guides, from words already on each page; the h1s are unchanged |

**When it shows:** the docs at `/` are built from the newest release tag (v0.12.0) and `main` goes to `/next/`. These changes appear at `/next/` when pushed and at `/` with the next release.

Left as proposals:

- **`/next/` is indexable and self-canonical**, and listed in `robots.txt`, so every page exists twice. Fix in jekyll-vitepress-theme (non-stable versions `noindex,follow`, out of `robots.txt`); it changes every site on the theme.
- The JSON-LD has no `SoftwareApplication` for the tool itself (name, operating systems, free, the RubyGems download). The theme would need a page-level hook for it.
- Links in: native-packages is used by ZapFast, Spotifast, TonePush, Solco and Chat with Work Desktop; a "packaged with native-packages" link from each app's download page or README would be the best links this site can get.
