0.9.0 builds Windows Installer (MSI) packages. A Windows target can now ship an `.msi` from your own WiX project, next to the DMG and Linux packages from the same configuration.

## New

- **Build an MSI from your Windows Installer project.** Select `msi` in a Windows target's `formats` and point `native.command` at the script that builds your installer, such as `wix build`. It works like `inno`: the tool copies the app, runs your recipe, checks that it produced exactly the declared `.msi` and that the file is a Windows Installer database, then records its checksum. By @crmne.
- **Tested end to end on Windows.** The Windows acceptance job builds an MSI fixture with WiX 5, then installs, upgrades, rolls back and removes it with `msiexec`, as it already does for Inno. By @crmne.

```yaml
windows-amd64:
  platform: windows
  arch: amd64
  formats: [msi]
  input:
    kind: directory
    local: dist/windows
  native:
    command: [ruby, packaging/msi.rb, '@PAYLOAD@', '@PACKAGE@', '@VERSION@']
    output: 'hello-@TAG@-windows-amd64.msi'
```

Read [macOS and Windows installers](https://native-packages.dev/native-recipes/#a-windows-installer-msi-project) for a minimal WiX project and build script.

## Known limitations

- native-packages does not generate the WiX project. Install location, shortcuts, file associations and closing a running app are part of your recipe.
- Windows Installer compares only the first three version fields, so release candidates of one version upgrade each other in place.
- The fixture is tested on x86-64 Windows. An ARM64 MSI builds from the same recipe with WiX's `-arch arm64`, but was not installed in CI.
