0.11.0 signs Windows apps. With Azure Artifact Signing configured, MSI and Inno builds sign your executables before the installer packs them, then the installer itself, so Windows names your organization as the publisher. It also writes a first Omarchy package for your app.

## New

- **Windows code signing with Azure Artifact Signing.** Add a `windows.signing` section, give the job the account's `AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT` and `AZURE_SIGNING_PROFILE`, and sign in to Azure first (`az login`, or `azure/login` with OIDC in GitHub Actions, so no secret is stored). MSI and Inno builds then sign the unsigned executables and libraries in their input copy, run your recipe, and sign the installer before recording its checksum. Every signature uses SHA-256 and Microsoft's RFC 3161 timestamp, and is checked afterwards, including the publisher you expect. By @crmne.
- **`sign-windows` for everything else.** `native-packages sign-windows FILE...` signs and checks files built outside native-packages, such as the executable in a portable ZIP or a setup program your workflow compiles. By @crmne.
- **A first Omarchy package.** `native-packages omarchy-recipe CHECKOUT --release TAG` writes `pkgbuilds/NAME-bin/` into an omarchy-pkgs checkout from your AUR `-bin` templates, with an update watch on your GitHub releases, so Omarchy's bot keeps it current. By @crmne.

```yaml
windows:
  signing:
    provider: azure-artifact-signing
    description: Hello
    publisher: Example Ltd
```

Read [Windows code signing](https://native-packages.dev/windows-signing/) for the Azure account, the GitHub environment, and the federated credential. Many repositories now present GitHub's immutable OIDC subject, `repo:OWNER@OWNER_ID/REPOSITORY@REPOSITORY_ID:environment:NAME`; a credential with the plain `repo:OWNER/REPOSITORY:...` form then fails with `AADSTS700213`, and the guide shows how to read the right one.

## Known limitations

- Azure Artifact Signing is the only provider. Other certificates still sign through an `after_package` hook.
- MSIX packages are not signed automatically: their manifest must name the certificate's exact subject.
- Signing runs on x64 Windows. SignTool and the Artifact Signing client are downloaded from nuget.org on first use, at pinned versions checked by SHA-256, unless you point `NATIVE_PACKAGES_SIGNTOOL` and `NATIVE_PACKAGES_ARTIFACT_SIGNING_DLIB` at local copies.
